# Data Model: Learning Reflector

## Learning Result

Represents the model's assessment of the latest user message.

| Field | Type | Constraints |
|---|---|---|
| `hasLearning` | boolean | Required |
| `fact` | string or `null` | Required; `null` when no learning is proposed; when `hasLearning` is true, non-empty after trimming |

### Validation and lifecycle

- The result is validated before any memory operation.
- `hasLearning: false` always means no persistence, regardless of `fact`.
- `hasLearning: true` with a null, empty, non-durable, or credential-like fact means no
  persistence.
- The result contains at most one fact and is derived only from the latest user message.
- It is transient and is not stored as a separate database record.

## Durable Fact

A stable preference or reusable user context that may improve future assistance. It uses the
existing `Memory` fields and persistence contract:

- `id`: generated unique identifier.
- `userId`: active user identifier from the chat context.
- `fact`: normalized non-empty durable fact.
- `embedding`: generated by the existing memory store.
- `createdAt`: set by the existing memory store when inserted.

The learning process must not persist one-off requests, task instructions, or authentication
secrets. The existing per-user deduplication rule remains unchanged.

## Forget Preference Request

| Field | Type | Constraints |
|---|---|---|
| `fact` | string | Required, non-empty after trimming; exact fact to forget |
| `userId` | string | Required trusted context; never supplied by the model as a tool argument |

The tool returns whether an exact fact was removed. It does not expose or modify another user's
memories. A missing match leaves all memories unchanged.

## Relationships

- One active user may own many durable facts.
- Each learning result may produce zero or one durable fact for its active user.
- A forget request targets one fact belonging to one active user.
- The model assessment is transient; only accepted facts become user memories.

## State Transitions

```text
successful chat answer
  -> assess latest user message
      -> hasLearning=false -----------------> no write
      -> invalid / empty / non-durable /
         credential-like fact --------------> no write
      -> valid durable fact -----------------> remember for active user

user asks to forget a preference
  -> forget_preference(fact, trusted userId)
      -> exact match ------------------------> report removed
      -> no match ---------------------------> report no match; preserve other facts
```
